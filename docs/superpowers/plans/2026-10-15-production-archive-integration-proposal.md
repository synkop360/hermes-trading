# Proposed production archive integration — approval required

## Decision and scope

The approved offline prototypes preserve accounting, lifetime counts, legacy partial entries and LLM review state. They do not solve running-worker storage by themselves. Proposed next heavy change: implement archive-aware runtime components locally behind a disabled configuration, then verify them only against synthetic data and faults. Keep Railway execution, all eight wallets, one-minute common inputs, existing risk/expense rules and five-close LLM cadence.

This proposal requests implementation and correctness testing only. Deployment, live evidence retirement, trading activation, paid services, paid inference, training and economic backtests require separate authorization. The declined5GB resize remains declined.

## Components and invariants

1. **Single writer and snapshot boundary.** Acquire the existing worker ownership boundary; freeze only a completed common batch when no batch/publication/lease is unresolved. Produce a SQLite-consistent backup with an exact inventory of account/source/history/strategy/review/expense/control state. Do not copy an active database plus arbitrary WAL bytes. Bound pause/export time so protective processing remains available; cancel and retain original evidence on timeout.
2. **Immutable archive publisher.** Export content-addressed evidence to the existing E: target, validate all objects/manifests and restore the committed snapshot. A transport provides authenticated bounded messages and resumable transfers, with no public unauthenticated endpoint. Installation must fail closed unless an actual verified transport and independently recoverable second-copy policy are supplied. A signature alone cannot satisfy that policy.
3. **Durable operation protocol.** Persist a request keyed by operation ID and the precise experiment/release/cohort/cut/revision/prefix hashes. Receipt authentication uses purpose separation and a strict validity window; accepted receipt and operation state survive acknowledgement loss/restart. Re-signing or retrying an operation cannot create a new retirement authorization. Shared journal checkpoint and prefix deletion commit atomically with the operation transition in the same database. Per-account transitions use a durable recoverable cohort state machine; partially retired accounts cannot publish mixed evidence or resume collection. Do not combine independent nonce commits with deletion and claim atomicity.
4. **Archive-aware runtime readers.** Replace retained-row lifetime counts with validated checkpoint-plus-suffix counts. Keep original max-cycle/time limits and nondecreasing trusted external witnesses. Preserve cumulative ordinary/stressed cash, open-entry contracts, expense accrual, peaks/halts, canonical IDs, and publication/projection state. Full accounting/report reads merge original archive evidence with current state and reject gaps, conflicts or unrelated identities. Inability to fetch history prevents normal entries and reports qualification as incomplete; protective exits remain available from locally retained original entry state.
5. **LLM evidence.** Retain every unresolved closed ID and recovery classification independently of latest25 prompt context; preserve consumed IDs, pending review/candidate and model-attempt budgets. Archive-aware union must not dispatch a review twice or reset the5-close watermark. Keep current supervisor/strategy-owner rules.
6. **Space and outage controls.** Measure total active files plus SQLite WAL, checkpoints, staging, transfer and recovery peaks across the entire eight-account cohort. Enforce a configured verified byte ceiling with the existing recovery reserve before export or collection. Unknown/unbounded capacity cannot qualify launch. PC/transport/second-copy outage retains source evidence, blocks retirement and stops normal collection/entries early enough to preserve protective processing. Do not silently reduce cadence/accounts, drop evidence or erase costs to fit.
7. **Recovery and rollback.** Retain the last verified snapshot/checkpoint and full old-version entry contracts. Simulate power/transfer interruption, missing/corrupt objects, stale/replayed receipts, lost acknowledgement after commit, concurrent writer, partial cohort transition, rollback of local state, disk-full and restored receiver operation state. Resume only after exact experiment/release/count/prefix reconciliation. Configuration defaults disabled; rollback disables retirement while retaining archive/source evidence.

## Acceptance evidence

- Native worker, without an in-memory test adapter, stops at original lifetime limits after repeated archival and restarts.
- Uninterrupted versus archived/continued eight-account fixtures have equal original orders/fees/lineages, ordinary/stressed net liquidation, expense state, risk halts, next common inputs, review eligibility/context and model budgets. All source data is synthetic; no economic outcome claim.
- Original partial positions remain manageable with provider/archive unavailable. Incomplete history cannot hide recovery flags or qualify profitability.
- Bounded space/export latency are measured under faults and full state churn; capacity is reported only for the tested workload and explicit reserve, never extrapolated as an upper bound without enforcement.
- Windows checks plus Linux checks when the existing Docker engine is available; existing full runtime regression suite after product edits. Independent code review, source fingerprints and a disabled release artifact.

## Remaining launch decisions

Actual independent backup/transport destination, expense accounting, account fees/access, current pinned-model proof, identity/inception and single-writer cutover still need verified evidence. Neither this proposal nor its future correctness tests demonstrate a winning strategy. Prospective paired paper outcomes remain necessary before assessing returns or the minimum economically viable wallet.
