# Bounded paired paper worker

Continue the approved recovery goal with a runnable worker for the verified shared-batch core. This does not authorize a new paid service or real order. Staged profiles remain unactivated until the operational source/configuration preflight and reviewed release are concrete.

The worker owns one finite experiment, one common public-price collector and eight isolated virtual accounts. It never invokes an exchange order API or an LLM. External proposal-only supervision remains the sole strategy writer. Use the existing MarketDataCoordinator/PriceClient infrastructure with explicit public-price-only dependencies; do not silently activate paid news/tools. Five-minute observation freshness requires a polling interval below that boundary, with collection/processing delay reported.

Persist experiment identity and finite time/cycle bounds before collection in a separate durable runtime database. Hold an exclusive process lease through the loop and sleep, separate from the per-batch publication lease, so a second worker cannot interleave batches while the first sleeps. Restart preserves original capital, inception, bounds, completed-batch accounting and pending common packets. Existing core state without a recorded worker lifecycle requires reconciliation, not a new deadline. Interrupted batches complete from frozen data before publication/new collection.

Capture package release and owner policy at startup. Compare current disk release against that binding before each cycle; prevent entries on invalid configuration while preserving explicitly possible protective processing. Publish primary/suite heartbeat with mode=paper, execution=simulated, causal observed strategy versions, startup identity, completed batch and input hashes, all eight net wallet/risk states, source freshness, model readiness and always-blocked real-trading qualification. Bind primary wallet report to the heartbeat so existing supervisor snapshots can verify the actual observed version. Expose degraded/missing facts instead of a healthy flag after an incomplete batch.

Checkpoint reporting at day30 is an operational/learning report, not a profit qualification. The finite final protocol can extend to the preregistered180-day assessment; neither a restart nor a fresh launch may reset those dates. At the bound or explicit stop, persist terminal state before exit. Report outstanding simulated inventory and continuing expenses. Railway process exit does not prove hosting charges stopped: deployment must include an explicit restart/service-stop policy. A terminal experiment must never auto-resume trading because the platform restarts it.

Verification: draft/readiness rejection before collection; one collector across eight accounts; exclusive worker ownership; original deadline/cycle preservation on restart; partial-batch replay; startup/disk and policy mismatch; causal version/report heartbeat binding; model/access degradation without implicit fallback; observed checkpoint versus qualification; finite stop without fake fills or expense resets. Tests use fixtures; no new backtest/model call/operational launch is part of this implementation stage.

Still required: live cumulative expense adapters including fixed subscription/hosting allocations and explicit FX provenance, finalized activation/release artifact, prospective observations, statistical qualification/lineage/stress verification. Model connectivity is proven separately; it does not establish a winning strategy.
