# V2 export and recovery: remaining contract

Read-only mapping during the approved disabled archive implementation. These are constraints for the next implementation step, not a completed export design, an installed service or launch qualification. Preserve the original eight accounts, financial evidence, review state, cycle count and deadline. No market backtest, paid model call or trading activation is involved.

The existing `archive_receiver_export.py` remains a V1 format. Its fingerprint requires `witness_meta` / `witness_events` and rowid ordering; its certificate validates a V1 head, its ZIP format has exactly two members, and its export calls a V1-only receiver preparation signature. Reusing that exporter unchanged would neither export a V2 receiver nor recover its replay evidence.

A coherent V2 cut must include the original receiver database, dedicated bounded nonce database and a purpose-bound certificate. Acquire the retained storage-domain owner before opening either database; preserve original file identities, receiver head, external nonce generation and configuration. Snapshot without inventing a nonce acceptance, advancing an acceptance floor, pruning rows, resetting storage or releasing ownership between the two snapshots. `nonce_entries` is `WITHOUT ROWID`: a deterministic logical fingerprint must use nonce order. The new nonce adapter currently has no validated non-mutating snapshot interface, so raw copying or private-connection borrowing is not an implemented export API.

Admit the entire additional backup, archive, certificate and staging peak in the destination domain before creating a stage. Preserve the original bounded export and restore deadlines and count retained old exports. Independent transfer and verification must succeed before source retirement. A same-PC copy is not an independent backup. The prepared receiver's exclusive handle means an exporter cannot simply open another connection behind its retained owner; it needs the same coordinator and a defined owned snapshot operation.

Recovery must verify a caller-retained independent anchor. The receiver and nonce in-memory floors disappear with the process. The external nonce store ID detects a different generation, but an older same-generation pair may still have that same ID. `accepted_floor_us` is also insufficient as a transaction sequence: several accepted nonces can share one timestamp. An exact authorized offline cut can bind the full archive/certificate digest and deterministic nonce-row digest. Accepting a later cut requires authenticated monotone evidence; it must not silently select whichever files were restored.

The recovery anchor must also account for unresolved requests and offline protective claims created after the last export. Restoring only the last exported receiver head can lose those claims. Keep resumption and retirement disabled until this is reconciled with the source's original frozen packets, whole-cohort state and external high-water evidence.

Before implementation, settle the bounded certificate format, validated snapshot APIs, externally retained cut/floor lifecycle and coordinator ownership. Then add real-file stale-pair, same-timestamp nonce loss, partial publication, lost acknowledgement, destination-full and eight-account recovery tests. Complete installed root inventory, all-writer participation, exhaustive temporary-file peaks, full-horizon combined capacity and final whole-release verification remain separate gates.
