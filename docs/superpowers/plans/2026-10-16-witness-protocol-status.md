# Collection reservation protocol — local implementation status

Part of approved archive integration task3. This is local correctness work. No receiver, network route, credentials, trading activation or deployment has been installed.

The native worker accepts an optional `archive_witness` object in `worker_limits.json`, with exactly `schema_version: 1`, a `binding` containing the pinned `witness_id` and `genesis_sha256`, and `identity_sha256`. Presence requires an explicitly injected client. Absence keeps the feature disabled. An adapter without the configuration is also rejected. None of the current draft wallet configurations is enabled by this implementation.

Identity includes experiment, cohort manifest, package release, owner policy, all eight account configurations and goal bytes, original storage and worker bounds, and the original activation-derived deadline. The witness configuration is excluded from the identity digest to avoid a recursive genesis dependency; the complete worker configuration, including this binding, remains pinned by its existing lifecycle hash.

Before collection, the worker obtains the receiver head and derives an original source view from the checkpoint plus retained contiguous shared journal. It verifies the old prefix, current lifetime count and archive revision, and requests a reservation for exactly the next common eight-account batch. The original packet freezes that reservation ID. Restart may replay a matching original pending packet; a completed packet can acknowledge the outstanding reservation. Lost acknowledgement does not allocate another slot. A restored source behind the receiver is rejected before another collection. Unchanged checks do not grow the event chain.

An outstanding reservation with no original pending packet is ambiguous. The worker never cancels it automatically, including after a known pre-freeze collection error. The receiver's explicit cancel API identifies a deliberate trusted recovery decision; possession of the token does not prove that cancellation is safe. No recovery decision or live data modification was performed here.

The injected adapter contract has `read(binding, identity, timeout)` and `apply(view, binding, identity, action, expected_head_sha256, operation_id, timeout)` keyword arguments. Each call receives a ten-second bound. An installed implementation must actually enforce that bound, authenticate/pin the intended receiver and response, retain anti-replay evidence, and use receiver time for deadline admission. Python callbacks cannot be preempted by this interface. The test adapter uses an isolated local SQLite receiver and proves protocol behavior only.

`archive_witness_transport.WitnessClient` now implements that worker contract over an injected exchange. Both client and server default disabled. Canonical HMAC requests and responses have different purpose domains; response signatures bind the fresh request nonce, the entire request digest, fixed receiver genesis/identity and returned head. Requests expire at age300s and reject future timestamps. The server requires the existing durable SQLite nonce store, with replay rejection verified after reopening it. Read/check/reserve are the only remote actions; cancellation, initialization and retirement are unavailable. Lost-reply retry uses a new authentication nonce while retaining the exact original operation ID/body and CAS head. The native worker runs through this signed protocol in synthetic tests, including rejecting response tampering before collection and degrading its heartbeat.

Protocol bodies are capped at8KiB and combined serialized request/response JSON at16KiB. The exchange receives the remaining response byte budget and at-most10s timeout. These are application-message bounds; there is still no installed socket/process/network exchange, key or receiver service, and no proof that an arbitrary callback interrupts blocking I/O. Nonce database/control-state footprint remains part of the unfinished aggregate capacity work. Signing a source view authenticates its trusted sender; it does not independently certify its financial contents or backup independence.

`archive_witness_socket.SocketExchange` now supplies a real, disabled-by-default socket implementation for that exchange contract. It uses an explicitly configured numeric address, avoiding DNS/proxy/redirect behavior inside a request, and a fixed POST path. TLS verifies the configured server name and CA; there is no certificate-verification bypass or plaintext fallback. An explicit CA file loads only into that connection context, never the OS trust store. Plaintext is allowed only through an explicit loopback option. Numeric route changes require an out-of-band reviewed configuration update; routing/ingress and independent host selection are not installed or certified here.

The socket applies the remaining absolute deadline to connect, TLS handshake, sends and every receive, so drip-fed data cannot reset the timer. HTTP headers are capped at4KiB/32fields; body length is checked before reading/decoding. Duplicate headers/JSON keys, noncanonical lengths, chunked or compressed bodies, redirects and malformed/truncated frames are rejected. The existing signed protocol still enforces its application-message budget; HTTP/TLS/TCP overhead is not a bandwidth quota. Socket I/O is bounded; cooperative backend/database checks do not become a guarantee against stalled filesystem I/O or OS scheduling delays.

`LoopbackWitnessService` is also disabled by default and rejects non-loopback binds. It handles one connection at a time in the receiver owner thread and supports TLS with an explicitly supplied server context. The prepared receiver and durable nonce repository must be created/used/closed in that same thread; no threaded request pool may bypass their ownership. Invalid framing is rejected before witness dispatch; generic errors disclose no request bodies, paths or keys. Startup, key provisioning, external ingress, a supervised deployment and receiver-owned evidence export remain separate unfinished work.

The actual eight-wallet worker completed bounded batches, replayed a partially executed original packet without recollecting, and blocked collection after a lost reservation reply. Oversized/ambiguous framing, drip-fed responses and slow request recovery were checked. Receiver events are bounded per event and by an absolute event count. `read` and `apply` now accept a finite `timeout_seconds` of at most10 and a positive `max_bytes` of at most4GiB. The default maximum is a ceiling, not a disk allocation or a capacity reservation. Preflight counts the receiver database and its WAL/SHM/rollback sidecars. Reads do not require space for another event. Writes require rollback-journal mode, admit a conservative main/journal peak and set an actual SQLite main-file page ceiling. Time checks between original events and a SQLite progress callback interrupt CPU/SQL verification; deadline expiry before commit rolls back the reservation. SQLite also rejects oversized corrupt rows before JSON decoding. Existing history is never reset to fit a limit.

These are receiver-local controls, not an aggregate filesystem quota or a verified whole-state peak certificate. An unrelated process can change available space, and an uninterruptible filesystem call still needs a separate transport/process timeout. Verification scans the retained transition chain; stopping at a deadline does not prove that a six-month history can remain serviceable within it. Receiver state, memory/verification cost and independent recovery must be included in the remaining capacity work. Checksums establish internal consistency, not authenticity or independence from a whole-host rollback. A separate path on the same computer does not certify an independent witness or backup.

Receiver-owned export is now implemented as a separately disabled local API. It pins the current head, retains the exclusive owner connection/gate, uses SQLite backup and compares every original schema/row value. A single ZIP_STORED artifact contains only receiver.sqlite and a bounded certificate; no secrets or nonce repository are included. ZIP64, compression, arbitrary members, comments and oversized central directories are rejected. Atomic hard-link publication never replaces an existing target; unsupported filesystems fail closed. Destination faults retain a healthy source. Pending reservations are preserved, never implicitly cancelled, and neither export nor restore authorizes retirement.

Restore requires the pinned artifact SHA, binding/identity and original head. It checks the complete original event chain before publishing a new SQLite database. A forged certificate with recomputed byte/row checksums cannot bypass that verification. The native eight-account copy test compares all account rows and resumes an already bounded two-cycle worker without extra collection; it retains the original nonce repository/source and does not prove ongoing-position or complete disaster recovery.
