## Read-only work and locking

The snapshot reads selected manifest/account context, owner/goal/strategy, trades, heartbeat, wallet metrics and the 129 runtime source hashes; it probes the recorded worker PID's liveness. It rereads configuration/account/primary context to reject changes during collection (`supervisor_sync.py:136–164`). It does not initialize/migrate a database, dispatch a model, publish a strategy, renew access, write a health receipt or change a financial row. This command is different from running the whole watcher.

There are **two** `assert_no_pending_paired_batch` calls, before and after collection (`supervisor_sync.py:143,163`). Their existing shared-journal open uses SQLite URI **mode=ro, timeout=0** (`paper_publication.py:154–194`). The check also calls quote/cohort integrity validators, which open existing account databases in mode=ro, timeout=0, including all eight profiles even while archive features are disabled (`archive_quote_state.py:139–146,183–198`). This is validation, not archive activation. No immutable override, retry or guard relaxation is present. OperationalError inside the guarded inspection block is rethrown as ValueError with the fixed classification `paired batch/publication lease is busy`. It can originate from a shared or account read; the classification alone does not identify a database. The initial sqlite3.connect precedes that try block, so a connection failure can instead escape as its original OperationalError.

## Existing rejection families

- Boundary/integrity: a durable experiment storage halt, incomplete quote/cohort controls, missing selected journal/identity/risk state, wrong manifest identity, pending common batch or global primary risk halt (`paper_publication.py:154–194`).
- Read/parse/identity: missing or unreadable files, malformed JSON/YAML/trade rows, wrong selected primary/account/owner/protocol, configuration changes during collection or runtime-release mismatch (`supervisor_sync.py:56–81,136–164`; `paired_primary.py:108–118`).
- Worker evidence: status not ok; paired lifecycle not running/model_ready not true; invalid/stale quote (300 seconds) or candle (two timeframe intervals); non-paper/non-simulated mode; heartbeat stale/future (600 seconds); startup release, UUID/PID liveness or observed strategy-version mismatch (`supervisor_sync.py:82–114`).
- Wallet evidence: report missing, not observed/wrong experiment, heartbeat/report hash mismatch, report stale/future (600 seconds), or selected account/currency/capital mismatch (`supervisor_sync.py:115–132`). Atomic publication of each JSON file does not itself make a multi-file read coherent; this code rejects an incoherent hash pair rather than accepting it.

An uncaught failure in these paths causes the Python CLI to exit nonzero and emit a traceback; main does not map it to a typed status or retry. Invalid argparse usage normally exits2. Startup/import failure can also occur before main. These are source-supported exit possibilities, **not a diagnosis or probability ranking for the captured failure**. The paper supervisor entry-admission latch itself is not tested by validate_snapshot; a healthy worker can supply a valid snapshot while new entries remain blocked.
